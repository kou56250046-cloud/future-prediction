この解説の読み方

このタブには性質の違う2種類の情報が並んでいます。

  • データ — 求人票での出現率を比べた、過去の変化の分類（急伸・伸び・横ばい・減少・急減・件数不足）。ビルドのたびに計算し直します
  • 見立て — 今後そのスキルの必要性が増えるか減るかについての執筆者の考え（増える・減る・横ばい・不明）。手で書いた文章で、データではありません

「直近1年」は 2025-Q3〜2026-Q2 と 2024-Q3〜2025-Q2、「3年」は直近と 2022-Q3〜2023-Q2 を比べています。 4四半期ずつ束ねるのは季節による揺れを消すためです。 収集が月末まで済んだ四半期だけを使い、集計途中の四半期は含めていません。

差が「ある」と言うのは、2つの窓の出現件数が合わせて 20 件以上あり、比率の差が統計的にはっきりしていて（z ≥ 2）、相対的にも 15% 以上動いたときだけです。 急伸は相対 +50% 以上、急減は -33% 以下です。

ダッシュボードの「スキルの需要」は直近月の前年同月差で並べているので、ここと顔ぶれが違うことがあります。直近月は月の途中で件数が少なく、揺れが大きいためです。傾向を読むときはこちらを見てください。

総論

AI がコードを書く量が増えるほど、価値が移る先は「書くこと」から「何を作るかを決め、正しく動くことを確かめ、本番で動かし続けること」になると見ている。そのため、特定の言語やフレームワークの文法を知っていること自体の値打ちは下がり、型・テスト・CI のように機械が書いたものを機械で検証する仕組みと、データベースやクラウドのように障害の責任を人が負う層の値打ちが上がる。AI 系では、モデルを作る技術より、既存のモデルを業務に組み込む技術（エージェント、検索との組み合わせ、評価と運用）に需要が寄る。一方で、流行の早い段階で職種名やスキル名として独立していたもの（プロンプトエンジニアリング、特定のラッパーフレームワーク）は、基礎的な素養やより一般的な呼び名に吸収されて求人票から消えていくと見る。言語やフレームワークでは、すでに主流のもの（Python、TypeScript、React、Postgres）がさらに集中し、代替の多い中位のものが削られやすい。AI が学習した量の多い技術ほど AI の支援が効き、採用側がそれを選ぶ理由が増えるためである。ただしこれは執筆者の見立てで、特に「消える」側の予測は、求人票が語を書かなくなることと仕事が無くなることの区別がつきにくい点に注意してほしい。

「下がる」は求人票にその語が書かれなくなることを含む。仕事そのものが無くなるとは限らない

見立てを採点するには

このタブの見立ては採点されていません。自分でも同じように考えるなら、確率をつけて予測台帳に登録すると、期日にベースライン（現状維持・直線外挿）と比べて採点されます。値は自分で決めてください。下は形の例です。

次の内容を BOM なしの UTF-8 のファイル（例: prediction.json。エディタで保存する）に保存し、--file で渡します。 --json '…' でコマンドラインに直接書くと、Windows PowerShell では引数の " が取り除かれて読み取りに失敗します。

{
  "title": "AI エージェント / MCP の出現率は 2027Q4 に 18% を上回る",
  "category": "jobs",
  "tags": [
    "adoption"
  ],
  "p": 0.55,
  "rationale": "（ここに自分の根拠を書く。見立ての文章をそのまま写さない）",
  "resolveOn": "2028-01-15",
  "resolver": {
    "kind": "metric_threshold",
    "metric": "jobs.skill.share.ai_agents",
    "period": "2027-Q4",
    "op": ">",
    "value": 0.18,
    "minN": 300
  }
}
node scripts/predict-add.js --file prediction.json

指標名は node scripts/predict-add.js --metrics jobs.skill.share で探せる。登録前にベースラインの確率が表示され、自分の確率とほぼ同じなら登録が止まる。

注意

  • 語彙の固定 — config/taxonomy.json の語だけを数える。新しい技術は語彙に足すまで 0 のまま出る
  • 1つのキーが複数の語を束ねている — 各スキルの「数えている語」を見る（例: Ruby は rails も数える）。一般的な英単語と同じ綴りの語（spark、unity、node など）は、技術と関係ない出現も入る
  • 「AI（語としての言及）」はスキルではない — 製品や会社の紹介での言及も数えるので、まとめからは外している
  • 求人票1件あたりのスキルの数 — 求人票が長く詳しくなると、全体の出現率が上がって見える
  • 母集団 — Hacker News の求人は英語圏・新興企業寄り。Java、C#、PHP などの大企業や既存 Web の需要は小さく出る
  • 見立ての書き手 — 見立ては Claude（LLM）が執筆時点の一般的な知見で書いた。Anthropic API の項目は執筆者自身に関わる

このページは何か

AI の進化と IT 関連職のニーズの変化を定点観測し、自分の予測をベースラインと比べて採点するためのページです。

予測は確率つきで登録し、期日に機械で判定します。現状維持（いまの値が続く）と直線外挿（いまの傾きが続く）の両方に勝てていなければ、その予測は「できている」とは言いません。グラフはそのための材料で、眺めて納得するためのものではありません。

タブは3つです。

  • ダッシュボード — 採点結果とデータの推移
  • スキル解説 — スキルごとの変化の分類と、今後の見立て
  • 見方 — このタブ。各ブロックの読み方と用語

あなたの癖

何を見るか
言った確率の平均と実際の的中率の差を、ホライズン・タグ・カテゴリ・自信度別に並べたもの。
どう読むか

よくある誤読

何を見るか

よくある誤読
小さい点（件数の少ない帯）が対角線から離れていても、それだけで確率が狂っているとは言えない。

用語

用語意味
Brier スコア確率予測の誤差。(言った確率 − 結果[起きた=1, 起きない=0])² の平均。0 が完璧、常に 50% と言うと 0.25。小さいほど良い
skill score1 − 自分の Brier ÷ ベースラインの Brier。正ならそのベースラインより良く、0 以下なら負けている
ベースライン（4種）比べる相手の機械的な予測。現状維持（直近の値が続く）、直線外挿（最近の傾きが続く）、コイン投げ（常に 50%）、過去の的中率（同じカテゴリ・タグの予測で自分が当ててきた割合。判定済みが5件未満なら出さない）
較正言った確率と実際に起きた割合が一致しているか。70% と言ったことが 7 割起きていれば較正が取れている
需給比求人票の数 ÷ 求職者の書き込みの数（HN の月次スレッド）。1 を下回ると求職者の方が多い
出現率そのスキルの語を含む求人票の割合。1件の求人に何回出ても1と数える
前年同月差当月の出現率 − 12ヶ月前の出現率（pt）。比率ではなく差。四半期の指標では 4期前との差
分母 nその値を計算した求人票の件数。n が小さい期の値は揺れる。すべての指標が n を持っている
被覆率勤務形態や経験レベルなど、その属性を書いた求人の割合。低い期は「書いた求人だけの割合」が偏るので、閾値未満なら指標を出していない
生存者バイアス今も残っているものだけを見て過去を語る偏り。AI の系列は最新カタログのモデルを並べ直しているので、廃止されたモデルが入っていない
対数軸目盛りが掛け算で増える軸。10 → 100 → 1000 が等間隔に並ぶ。桁の違う値の推移を1枚で見るために使う
相関と因果2つの系列が一緒に動くこと（相関）と、一方が他方を動かしていること（因果）は別。時間とともに動く系列どうしは、無関係でも相関が出やすい
